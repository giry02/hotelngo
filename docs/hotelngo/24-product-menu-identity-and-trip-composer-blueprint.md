# HotelNGo 메뉴 정체성 및 다일정 여행 조합 기준선

- 작성일: 2026-07-24
- 목적: 현재 페이지를 전제로 하지 않고 고객의 여행 결정 과정을 기준으로 상단 메뉴와 하위 기능의 책임을 다시 정의한다.
- 핵심 시나리오: “다낭 4박 5일 동안 숙소, 랜드마크, 식사, 골프, 마사지, 이동을 날짜별로 조합하고 일부 또는 전체를 예약한다.”

## 1. 제품의 한 문장 정의

HotelNGo는 여행 콘텐츠를 구경하는 사이트도, 호텔 한 건을 예약하는 사이트도 아니다.

> 목적지를 발견하거나 선택한 뒤 숙소·랜드마크·식사·골프·마사지·투어·이동을 하나의 다일정 여행에 조합하고 예약 가능한 항목을 실제 예약으로 전환하는 여행 구성 플랫폼이다.

모든 고객 기능은 다음 흐름 중 한 지점에 속해야 한다.

```text
목적지 미정
→ 여행 욕구와 도시 발견
→ 목적지·날짜·인원 결정
→ 날짜별 여행 초안 생성
→ 숙소·장소·식사·활동·이동 추가
→ 시간·거리·운영·재고 검증
→ 일부 또는 전체 예약
→ 여행 중 일정과 바우처 사용
→ 후기·스토리 공유
```

## 2. 공통 여행 컨텍스트

호텔, 즐길거리, AI, 일정이 서로 다른 목적지와 날짜를 보여주지 않도록 다음 값을 공통 `TripContext`로 유지한다.

| 필드 | 설명 |
|---|---|
| `destinationId/name` | 국가·도시 또는 복수 도시 |
| `startDate/endDate` | 출발일부터 귀국일까지 |
| `nights/dayCount` | 숙박 수와 일정 일수 |
| `travelers` | 성인·아동·유아 및 동행 유형 |
| `origin` | 출발 공항·도시 |
| `budget` | 총액 또는 1인 예산 |
| `pace` | 여유·균형·촘촘 |
| `interests` | 바다·미식·골프·쇼핑·휴식 등 |
| `tripId` | 저장된 여행 초안 식별자 |

사용자가 컨텍스트 없이 호텔·즐길거리에 들어오면 무작위 추천을 먼저 확정하지 않는다. 목적지를 고르거나 “아직 미정—추천받기”를 선택하게 한다.

## 3. 상단 메뉴별 목표와 정체성

### 3.1 여행 발견

- 질문: “어디로 갈지 모르겠는데 가고 싶은 마음이 들게 해줘.”
- 역할: 예약 카탈로그가 아니라 도시·장면·테마·여행자 일정으로 목적지를 발견하는 영감 영역
- 입력: 목적지 미정 또는 선택한 도시, 계절, 분위기, 동행, 관심사
- 출력: 공식 여행 이야기, 랜드마크, 테마, 도시 가이드
- 핵심 행동: 도시 선택, 스토리 저장, 랜드마크 탐색, 여행기 메뉴로 이동
- 하지 않는 일: 재고를 확인하지 않은 콘텐츠를 예약 가능 상품으로 표현

하위 기능:

- 추천 도시와 테마
- 여행 스토리
- 랜드마크와 장면
- 도시 가이드
- 저장한 영감

### 3.2 여행기

- 질문: “실제 여행자가 다녀온 일정과 팁을 보고 내 여행에 활용하고 싶다.”
- 역할: 회원 공개 일정과 장면을 중심으로 한 참여형 콘텐츠 커뮤니티
- 입력: 목적지, 기간, 동행, 태그, 작성자, 좋아요·댓글·스크랩·팔로우
- 출력: 날짜별 여행기, 작성자 경험, 댓글 팁, 내 여행으로 복사 가능한 일정
- 핵심 행동: 좋아요, 댓글, 스크랩, 공유, 작성자 팔로우, 내 여행에 담기
- 하지 않는 일: 스크랩을 예약 확정이나 내 일정 생성으로 오인하게 표현

### 3.3 여행 일정

- 질문: “어디를 언제 누구와 가며, 매일 무엇을 할지 직접 짜고 싶다.”
- 역할: HotelNGo의 핵심 작업 공간. 한 여행 안에 여러 업종의 항목을 날짜·시간별로 조합
- 입력: 목적지, 날짜, 인원, 여행 성향
- 출력: 일자별 타임라인, 지도 동선, 예상비용, 예약 준비도, 충돌 경고
- 핵심 행동: 새 여행 생성, 항목 추가·이동·교체·삭제, 일자 복사, AI 보완, 저장·공유, 예약 준비

일정 항목 유형:

- 항공·공항 이동
- 숙소 체크인·숙박·체크아웃
- 랜드마크·관광지
- 음식점·카페
- 골프
- 마사지·스파
- 투어·체험
- 차량·교통
- 자유시간·메모

### 3.4 호텔

- 질문: “이 여행의 날짜와 위치에 맞는 숙소는 무엇인가?”
- 역할: 숙박 상품 탐색과 객실·요금·재고 비교
- 필수 입력: 목적지, 체크인·체크아웃, 인원·객실
- 출력: 호텔·객실·요금·정책·가용상태
- 핵심 행동: 비교, 상세·사진·후기 확인, 일정의 숙박 구간에 추가, 카트 또는 예약
- 일정 연계: 호텔을 추가하면 체크인·체크아웃과 숙박 구간이 모든 해당 일자에 반영

### 3.5 즐길거리

- 질문: “선택한 도시와 일정에서 무엇을 먹고 보고 경험할까?”
- 역할: 여행 일정에 넣을 현지 항목의 고객용 카탈로그
- 필수 입력: 목적지. 날짜가 있으면 운영·슬롯·거리 기준으로 우선 정렬
- 하위 분류: 랜드마크, 맛집·카페, 골프, 마사지·스파, 투어·체험, 차량·픽업
- 출력: 장소·상품·대표 이미지·소요시간·가격·예약방식·운영·이동 정보
- 핵심 행동: 상세보기, 저장, 특정 일자·시간에 추가, 대체 후보 비교
- 변경: 기존 `현지 장소` 상단 메뉴는 즐길거리와 중복되므로 제거하고 업체 상세·실제 상품 데이터는 즐길거리 내부에서 사용

### 3.6 AI 여행

- 질문: “조건을 말할 테니 전체 여행을 한 번에 짜고, 대화로 고치고 싶다.”
- 역할: 별도 여행 데이터가 아니라 수동 일정과 동일한 `TripDraft`를 만드는 생성·수정 도구
- 필수 입력: 목적지가 정해졌다면 도시·날짜·인원, 미정이라면 도시 추천 단계를 먼저 수행
- 결과: 숙소·랜드마크·식사·골프·마사지·투어·이동이 포함된 일자별 일정
- 수정 명령: 골프 추가, 식당 교체, 이동 축소, 호텔 변경, 하루 비우기, 예산 조정
- 핵심 원칙: AI 일정과 직접 일정은 같은 편집기·검증·예약 준비도를 사용

### 3.7 내 여행

- 질문: “만든 여행과 예약을 다시 보고 출발 전후로 관리하고 싶다.”
- 역할: 회원 소유 여행의 목록과 상태 관리
- 하위 기능: 초안, 예약 준비, 예약 진행, 확정 여행, 지난 여행, 공유받은 여행, 저장 항목
- 핵심 행동: 이어서 편집, 예약 준비도 확인, 바우처·취소·문의, 복사·공유, 후기 작성

## 4. 메뉴 간 이동 계약

| 출발 메뉴 | 다음 행동 | 전달해야 할 값 |
|---|---|---|
| 여행 발견 | 도시 선택 | 목적지 |
| 여행 발견 | 공개 일정 복사 | 목적지·기간·일정 항목·원본 출처 |
| 여행 일정 | 호텔 찾기 | 목적지·숙박일·인원·tripId |
| 여행 일정 | 즐길거리 찾기 | 목적지·선택 일자·관심 카테고리·tripId |
| 호텔 | 일정 추가 | hotel/product/offer, 체크인·체크아웃, 총액 |
| 즐길거리 | 일정 추가 | 장소/상품, 이용일·시간·소요시간·가격 |
| AI 여행 | 편집기로 전환 | 전체 `TripDraft` |
| 내 여행 | 예약 준비 | tripId와 항목별 예약 가능 상태 |

## 5. 다일정 데이터 모델

```text
Trip
 ├─ destination
 ├─ startDate / endDate / travelers
 ├─ preferences
 └─ days[]
     └─ items[]
         ├─ category
         ├─ sourceId / productId / offerId
         ├─ startTime / duration
         ├─ title / image / area
         ├─ priceSnapshot
         ├─ bookingType / availabilityStatus
         └─ notes
```

숙소는 한 번 선택하더라도 숙박 구간 전체와 연결된다. 다른 항목은 기본적으로 특정 일자·시간에 속한다. 단순 “1일차에 담기”는 금지하고 사용자가 대상 일자와 시간을 선택하거나 일정 편집기에서 배치한다.

## 6. 일정 편집기의 필수 동작

1. 목적지·날짜·인원을 먼저 설정
2. 4박이면 5개의 날짜 열 생성
3. 좌측 또는 상단 카테고리 카탈로그에서 항목 탐색
4. 추가할 때 일자·시간 선택
5. 같은 날에 숙소·관광·식사·활동·이동을 여러 개 배치
6. 시간순 정렬과 일자 이동
7. 항목 교체·삭제
8. 예상비용과 예약 가능 상태 집계
9. 숙소 없음, 식사 없음, 공항 이동 없음, 시간 충돌, 장거리 이동을 경고
10. 예약 가능한 항목만 카트로 전환

| `experiences.html` | 목적지 선택 없이 여러 도시 추천을 혼합 | 재구성 | 목적지 컨텍스트와 업종 필터가 있는 카탈로그로 변경 |
| 상단 `현지 장소` | 즐길거리와 책임 중복 | 상단 제거 | 즐길거리의 실제 업체·상품 상세 데이터로 흡수 |
| `ai-travel.html` | 랜드마크 중심 뼈대이며 숙소·식사·골프·이동이 빠짐 | 확장 | 전체 일정 편집기로 이어지는 다카테고리 초안 생성 |
| `hotels.html` | 목적지·날짜 입력은 있으나 tripId/숙박 구간 연결이 약함 | 보완 | 일정에서 진입 시 컨텍스트 유지 및 숙박 구간 추가 |
| `trips.html` | 정적 교토 보드와 저장 목록이 혼재 | 재구성 | 회원 여행 목록·상태·이어 편집 중심으로 정리 |
| `places.html` | 업체와 상품 데이터는 유용하나 고객 상단 메뉴로는 중복 | 유지·내부화 | 즐길거리 상세와 일정 추가의 데이터 공급 화면으로 사용 |

## 8. 인수 조건

- 4박 5일을 선택하면 5개 날짜가 생성된다.
- 한 날짜에 숙소, 랜드마크, 식사, 골프, 마사지, 차량 등 여러 항목을 추가할 수 있다.
- 각 항목은 일자·시간·소요시간·예약방식·가격을 가진다.
- 목적지 선택이 호텔·즐길거리·AI·일정 사이에서 유지된다.
- AI가 만든 여행도 같은 일정 편집기에서 수동으로 변경할 수 있다.
- 여행 발견은 목적지 미정 탐색과 목적지 선택 후 탐색을 구분한다.
- 즐길거리는 목적지를 선택하지 않은 상태에서 서로 다른 도시 상품을 예약 후보처럼 섞어 보여주지 않는다.
- 예약 준비 화면은 정보형·요청형·즉시예약형을 구분한다.

| 즐길거리 | 목적지 미선택 시 도시 선택 게이트, 선택 후 해당 도시 상품만 노출하고 업종 필터 제공 |
| AI 여행 | 호텔·픽업·맛집·골프·스파·호이안 요청을 같은 5일 편집기와 14개 일정으로 연결 |
| 내 여행 | 정적 보드 대신 저장된 여행 목록과 공통 편집기 진입을 중심으로 정리 |

## 10. 사용자 시나리오 검증

다음 시나리오를 로컬 브라우저에서 실제 버튼 동작으로 확인했다.

1. 여행 발견에서 다낭을 선택하면 다낭 이미지·설명·일정 CTA로 전환된다.
2. 일정 편집기에서 4박 5일과 성인 2명을 설정하면 5개 DAY가 생성된다.
3. 추천 초안에는 숙소·공항 이동·식사·랜드마크·골프·스파·투어가 모두 존재한다.
4. DAY 3 18:00에 스파를 추가하면 기존 골프·식사와 함께 같은 날 세 항목이 유지된다.
5. 즐길거리에서 목적지 미선택 시 상품을 섞어 노출하지 않으며, 다낭 선택 후 골프 필터에는 다낭 골프 후보만 나온다.
6. AI 여행에서 “다낭 4박 5일, 호텔·공항 픽업·맛집·18홀 골프·스파·호이안”을 요청하면 동일 편집기로 이동한다.
7. 추천 초안의 시간 충돌은 0건이며, 저장 시 다낭 4박 5일과 14개 일정이 Mock 여행 데이터에 기록된다.

## 11. 남은 실서비스 경계

- 현재 일정·가격·예약방식은 JSON Fixture와 브라우저 저장소를 이용한 Mock이다.
- 실제 호텔 가격·재고는 Hotel_PMS 채널 조회 후 다시 확인해야 하며, PMS 회원과 HotelNGo 회원은 공유하지 않는다.
- 골프·식당·스파·투어·차량은 파트너의 실제 Product·Offer·Slot API와 운영시간·지도 경로가 연결되어야 한다.
- AI는 실제 LLM/RAG가 아니며, 향후에도 LLM은 후보 생성과 설명만 담당하고 시간·거리·가격·재고는 도구 호출과 규칙 검증기로 확정한다.
- 결제·부분확정·취소·환불·정산은 화면 상태만 존재하며 실제 PG·원장·공급자 예약 API가 필요하다.
