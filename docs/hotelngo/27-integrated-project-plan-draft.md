# 1. 사업 개요

## 1.1 사업명

**HotelNGo — 해외여행 발견·구성·예약 플랫폼**

## 1.2 사업 정의

HotelNGo는 호텔 객실만 비교하는 OTA가 아니라, 여행자가 목적지를 발견하고 숙소·랜드마크·식사·골프·마사지·투어·이동을 하나의 다일정 여행으로 구성한 뒤 예약 가능한 항목을 실제 거래로 전환하도록 지원하는 플랫폼으로 구축한다.

```text
여행 욕구 형성
→ 목적지 발견 또는 직접 검색
→ 목적지·기간·인원 결정
→ 날짜별 여행 초안 구성
→ 호텔·장소·활동·식사·이동 조합
→ 시간·거리·운영시간·가격·재고 검증
→ 일부 또는 전체 예약
→ 여행 중 예약·바우처·변경 관리
→ 후기·스토리·공개 일정 공유
```

## 1.3 초기 사업 범위

- 한국인 해외여행 고객을 우선 대상으로 한다.
- 동남아 주요 도시와 해외호텔을 중심으로 시작한다.
- 호텔과 함께 골프·차량·음식점·마사지·투어를 일정에 조합한다.
- Hotel_PMS를 사용하는 호텔과 PMS를 사용하지 않는 호텔을 모두 수용한다.
- 미입점 현지 업체도 정보형 장소로 먼저 등록한 뒤 입점과 예약 상품으로 전환한다.
- 국내 숙소·펜션·캠핑·글램핑·대실은 초기 범위에서 제외하고 이후 확장 여부를 검토한다.

## 1.4 사업성 검토의 핵심 질문

1. 감성적인 여행 발견 경험이 일반 검색보다 더 많은 저장·일정 생성·예약 전환을 만들 수 있는가?
2. Hotel_PMS 호텔을 기반으로 초기 숙박 공급을 안정적으로 확보할 수 있는가?
3. 호텔 외 업종을 결합해 객단가와 수수료 수익을 높일 수 있는가?
4. 사용자가 여러 서비스를 직접 일정에 조합하거나 AI 초안을 수정하는 경험을 실제로 원하는가?
5. 플랫폼이 업체를 먼저 등록한 뒤 관심·문의 데이터를 바탕으로 입점을 유도할 수 있는가?
6. 공급자 수수료와 부가 수익이 고객 획득비용·콘텐츠·CS·정산 비용을 감당할 수 있는가?

# 2. 추진 배경과 해결하려는 문제

## 2.1 고객 문제

### 여행지는 정했지만 전체 일정을 만들기 어렵다

- 호텔·맛집·골프·마사지·이동을 서로 다른 사이트에서 찾아야 한다.
- 예약 정보가 분산되어 시간과 동선을 한 번에 확인하기 어렵다.
- 가격·재고·영업시간을 확인하며 4박 5일 전체를 구성하는 데 시간이 많이 든다.

### 여행지를 정하지 못한 고객에게 일반 OTA는 충분한 영감을 주지 못한다

- 가격과 할인 중심의 카드만으로는 현지 분위기를 상상하기 어렵다.
- 랜드마크·현지 시간대·소리·사람의 취향과 호텔 경험이 분리되어 있다.
- 콘텐츠를 보고 마음에 들어도 일정과 예약으로 이어지는 경로가 약하다.

### 다른 사람의 좋은 여행 일정을 재사용하기 어렵다

- SNS 게시물은 감상할 수 있지만 날짜별 일정으로 바로 복사하기 어렵다.
- 복사하더라도 출발일·인원·예약 가능 여부를 다시 검증할 수 없다.

## 2.2 공급자 문제

### 호텔

- PMS는 객실·요금·재고·예약 운영에는 적합하지만 B2C용 사진·스토리·주변 경험을 충분히 표현하기 어렵다.
- 개별 호텔은 자체 예약 채널과 해외 고객 접점을 확보하기 어렵다.

### 골프·차량·음식점·스파·투어 업체

- 단순 업체 소개만으로는 고객이 상품·시간·옵션·가격을 비교하기 어렵다.
- 업종마다 자원과 재고 방식이 달라 통합 여행 상품에 들어가기 어렵다.
- 작은 현지 업체는 별도 시스템을 구축하거나 해외 고객을 직접 유치하기 어렵다.

## 2.3 운영자 문제

- 미입점 업체 정보는 최신성·출처·소유권을 관리하기 어렵다.
- 업체 입점 전후로 중복 페이지가 생기기 쉽다.
- 여러 공급자의 예약·취소·환불·정산 상태를 하나의 주문에서 관리하기 어렵다.
- AI가 실제 가격·재고와 검수 콘텐츠를 구분하지 않으면 신뢰할 수 없는 일정을 만들 수 있다.

# 3. 서비스 비전과 목표

## 3.1 비전

> **“가보지 않아도 가본 듯한 여행 장면을 보여주고, 가고 싶은 마음을 실제 일정과 예약으로 연결한다.”**

## 3.2 서비스 목표

1. 목적지가 정해진 고객과 정해지지 않은 고객을 모두 수용한다.
2. 호텔과 현지 서비스를 하나의 여행 일정 안에서 구성한다.
3. 콘텐츠·일정·예약이 끊기지 않는 고객 여정을 제공한다.
4. 공급 방식이 달라도 고객에게 일관된 검색·상세·예약 경험을 제공한다.
5. 플랫폼·호텔·파트너·PMS의 데이터 책임과 계정을 분리한다.
6. AI가 추천한 일정도 사람이 직접 수정하고 검증할 수 있게 한다.

## 3.3 사업 목표

- Hotel_PMS 사용 호텔의 신규 B2C 판매 채널을 확보한다.
- 독립 호텔과 현지 업체를 단계적으로 입점시킨다.
- 여행 콘텐츠와 회원 일정을 고객 유입 자산으로 만든다.
- 호텔 단독 예약보다 현지 서비스 교차판매 비중을 높인다.
- 여행 전·중·후 데이터를 축적해 재방문과 개인화 추천 기반을 만든다.

# 4. 핵심 고객과 이용 상황

## 4.1 목적지 확정형 고객

- 이미 다낭·방콕·발리 등 목적지를 정했다.
- 호텔명 또는 여행지를 검색해 가격·객실·후기를 비교한다.
- 호텔 예약 후 골프·픽업·식사·마사지를 추가하고 싶다.

## 4.2 목적지 탐색형 고객

- 휴가는 정했지만 어디로 갈지 정하지 못했다.
- 사진·영상·랜드마크·테마·다른 여행자의 코스를 보고 결정한다.
- 마음에 든 일정을 복사해 자신의 날짜와 예산에 맞게 바꾼다.

## 4.3 직접 계획형 고객

- 4박 5일 동안 무엇을 할지 직접 세밀하게 구성하고 싶다.
- 호텔·식사·골프·마사지·이동을 날짜와 시간별로 배치한다.
- 시간 충돌과 이동량, 예상비용, 예약 가능 상태를 확인한다.

## 4.4 AI 도움형 고객

- 자연어로 원하는 여행을 설명하고 전체 초안을 받고 싶다.
- “골프를 한 번 추가해줘”, “부모님이 편하게 바꿔줘”처럼 수정하고 싶다.
- AI가 만든 결과를 직접 편집한 뒤 예약하고 싶다.

## 4.5 공급 고객

- Hotel_PMS를 사용하는 호텔
- PMS를 사용하지 않는 독립 호텔
- 골프장
- 렌터카·기사 차량·픽업 업체
- 음식점·카페
- 마사지·스파
- 투어·체험 업체

# 5. 핵심 가치와 차별점

## 5.1 여행을 검색하기 전에 가고 싶은 마음을 만든다

사진 나열이 아니라 현지의 시간·빛·소리·동선·식사·휴식을 하나의 이야기로 보여준다. 호텔은 잠만 자는 상품이 아니라 하루가 시작되고 끝나는 여행 장면으로 표현한다.

## 5.2 하나의 상품이 아니라 여행 전체를 구성한다

한 날짜에 숙소·랜드마크·식사·골프·스파·이동을 여러 개 배치한다. 사용자는 특정 상품 하나를 고르는 것이 아니라 여행 전체를 날짜별로 만든다.

## 5.3 발견·일정·예약을 하나의 데이터로 연결한다

- 스토리의 장소를 일정에 담는다.
- 공개 일정을 복사한다.
- 호텔과 즐길거리를 일정 날짜에 추가한다.
- 예약 가능한 항목만 카트로 보낸다.
- 예약 후에도 바우처·변경·문의와 일정 관계를 유지한다.

## 5.4 Hotel_PMS와 독립 입점을 동시에 지원한다

- PMS 호텔은 기존 객실·요금·재고·예약을 원천으로 사용한다.
- 독립 호텔과 액티비티 업체는 HotelNGo에서 상품·재고·슬롯을 운영한다.
- 고객 화면은 공급 방식과 관계없이 동일한 표현을 사용한다.

## 5.5 미입점 업체를 수요부터 만든다

플랫폼이 현지 업체와 장소를 출처와 함께 먼저 등록한다. 고객 저장·문의·일정 추가 데이터를 축적한 뒤 업체에 입점을 제안하고, 입점 업체는 기존 페이지를 인수한다.

## 5.6 회원이 만든 여행이 다시 상품 탐색 경로가 된다

회원과 가이드의 공개 일정을 다른 고객이 복사하고 수정한다. 공개 일정은 단순 게시물이 아니라 호텔·장소·상품·날짜 관계를 가진 구조화 데이터로 운영한다.

## 5.7 AI의 설명과 실제 거래 정보를 구분한다

AI는 여행 조건 해석과 일정 초안을 담당한다. 가격·재고·영업시간·거리·예약 상태는 PMS, 파트너 API, 지도, 규칙 검증 결과만 사용한다.

# 6. 사업 구조와 시스템 구성

```text
B2C 여행 플랫폼
├─ 여행 발견·스토리·랜드마크
├─ 호텔·즐길거리 검색
├─ 직접 여행 일정
├─ AI 여행
├─ 여행 카트·예약·결제
└─ 내 여행·후기·고객지원

호텔 콘텐츠센터
├─ 호텔·객실 사진
├─ 소개·정책·편의시설
└─ PMS 객실유형 공개 콘텐츠 매핑

액티비티 파트너센터
├─ 골프
├─ 차량·픽업
├─ 음식점·카페
├─ 마사지·스파
└─ 투어·체험

플랫폼 관리자
├─ 회원·파트너·업체 심사
├─ 장소 선등록·소유권 인수
├─ 콘텐츠·상품·예약·정산
├─ 고객지원·감사
└─ AI·RAG 검수

PMS 채널 운영
└─ Hotel_PMS 호텔·객실·요금·재고·예약 연동
```

각 시스템은 독립된 계정·권한·데이터 책임을 갖고 API와 공급 어댑터로 연결한다.

# 7. 비즈니스 모델과 수익 구조

## 7.1 거래 수수료

- 호텔 예약 중개 수수료
- 골프·차량·마사지·투어 예약 수수료
- 식사권·코스·쿠폰 판매 수수료
- 공급자·상품·확정 방식에 따라 수수료율을 분리한다.

## 7.2 요청 예약·견적 전환 수익

실시간 재고를 제공하기 어려운 업체에는 요청 예약 또는 견적 요청을 제공한다. 유효 리드, 예약 확정, 거래 완료 중 어떤 시점에 과금할지 업종별로 검증한다.

## 7.3 결합 상품 수익

- 호텔+골프
- 호텔+공항 픽업
- 호텔+마사지
- 호텔+투어

결합 혜택은 각각의 재고를 합치지 않고 별도 예약한 뒤 하나의 여행 주문에서 묶는다. 할인 부담 주체와 정산 기준을 명확히 기록한다.

## 7.4 프로모션·광고

- 도시·테마·호텔·업체 추천 영역
- 검색 결과와 스토리 내 스폰서 콘텐츠
- 앱·회원 전용 쿠폰 캠페인

광고와 일반 추천을 시각적·정책적으로 구분하며, 검증되지 않은 업체를 예약 추천으로 표시하지 않는다.

## 7.5 제휴·외부 예약

직접 예약 기반이 없는 상품은 공식 외부 링크나 제휴 링크로 연결할 수 있다. 외부 거래 여부와 고객지원 범위를 명확히 표시한다.

## 7.6 향후 B2B 수익

- 호텔 콘텐츠 관리 고급 기능
- 파트너 운영·통계 고급 기능
- 외부 공급자·채널 연동 사용료
- 여행 콘텐츠·일정 API

초기에는 거래 수수료와 공급 확보에 집중하고, SaaS 요금은 공급자 가치가 검증된 뒤 도입한다.

# 8. 시장 환경·경쟁 구도·성장 전략

## 8.1 시장 검토 범위

사업계획서 최종본에서는 다음 시장을 분리해 규모·성장률·거래액·고객 행동을 조사한다.

- 한국인 해외여행과 동남아 자유여행
- 해외호텔 온라인 예약
- 현지 투어·액티비티·골프·차량 예약
- 여행 일정 작성·공유 서비스
- 생성형 AI 여행 추천
- 호텔 PMS 연계 B2C 판매 채널

시장 수치는 조사 기준 연도, 조사기관, 포함 업종, 거래액과 매출의 차이를 명시하고 동일 기준끼리 비교한다.

## 8.2 경쟁 구도와 차별화 가설

| 서비스 유형 | 일반적인 강점 | 고객이 겪을 수 있는 단절 | HotelNGo 차별화 가설 |
|---|---|---|---|
| 종합 OTA | 호텔 공급·가격 비교·결제 | 여행 영감과 날짜별 전체 일정이 약함 | 호텔 예약을 전체 여행 일정과 연결 |
| 여행 콘텐츠·SNS | 감성·영상·공유 | 실재고·예약·일정 편집이 약함 | 스토리를 구조화 일정과 상품으로 전환 |
| 일정 플래너 | 날짜별 구성·협업 | 공급자 가격·재고·예약이 약함 | PMS·파트너 공급을 같은 일정에 연결 |
| 현지 액티비티 플랫폼 | 투어·티켓 상품 | 호텔 PMS·숙박 구간·회원 일정과 분리 | 숙박을 중심으로 다업종 교차판매 |
| 호텔 자체 채널 | 호텔 정보·직접 예약 | 도시 콘텐츠와 주변 경험이 제한됨 | 호텔에서 시작하는 하루와 현지 상품 연결 |

차별화는 기능의 존재만으로 인정하지 않는다. 고객 전환율, 일정 내 복수 업종 비율, 공급 확보 비용, 예약당 공헌이익으로 검증한다.

## 8.3 도시 단위 집중 전략

초기에는 여러 국가를 얕게 다루지 않고 호텔·랜드마크·현지 서비스·이동·콘텐츠를 한 도시에서 충분히 연결한다.

권장 검증 순서:

1. 다낭
2. 방콕
3. 발리
4. 성과가 검증된 여행 유형과 유사한 도시

최종 출시 도시는 호텔 공급, 항공 접근성, 한국인 수요, 현지 파트너 확보 가능성, CS 난이도를 함께 평가해 결정한다.

## 8.4 수요 확보

- 도시·랜드마크·테마 SEO 콘텐츠
- SNS형 여행 장면과 짧은 영상
- 크리에이터·가이드 공개 일정
- 회원 일정 공유와 복사
- PMS 호텔의 기존 고객 접점
- 호텔·현지 업체 공동 프로모션
- 저장한 여행과 가격·재고 알림

## 8.5 공급 확보

- Hotel_PMS 호텔을 초기 숙박 앵커 공급으로 활용한다.
- 플랫폼이 현지 업체를 먼저 조사·등록한다.
- 고객 저장·조회·문의가 발생한 업체를 우선 입점시킨다.
- 업종별로 정보형 → 요청예약 → 즉시예약 순서로 전환한다.
- 현지 운영 대행 또는 파트너 성공팀을 두어 상품·사진·슬롯 등록을 지원한다.

## 8.6 확장 원칙

도시 확장은 다음 조건을 충족할 때 진행한다.

- 핵심 호텔 공급 확보
- 공항 이동과 주요 관광 동선 확보
- 각 핵심 업종의 선택 가능한 상품 수 확보
- 고객지원·취소·정산 운영 가능
- 콘텐츠와 실제 예약 정보의 최신성 확보

# 9. 공급자 확보와 입점 전략

## 9.1 공급 방식

| 공급 방식 | 운영 주체 | 적용 |
|---|---|---|
| `INTERNAL_PMS` | Hotel_PMS | PMS 사용 호텔 |
| `PARTNER_MANAGED` | HotelNGo 파트너 | 독립 호텔·현지 업체 |
| `EXTERNAL_API` | 외부 PMS·채널·공급사 | 외부 공급 상품 |
| `PLATFORM_CURATED` | 플랫폼 운영자 | 미입점 정보형 업체 |
| `HYBRID_MANAGED` | 플랫폼+업체 | 공동 관리 콘텐츠 |

## 9.2 미입점 업체 선등록

플랫폼은 파트너 계정 없이도 Provider와 Place를 등록할 수 있게 한다.

- 업체명·현지어명·영문명
- 유형·국가·도시·지역
- 주소·좌표·연락처·공식 채널
- 소개·대표 이미지·갤러리
- 운영시간·휴무일·가격대
- 제공 서비스·편의시설
- 출처·수집일·최근 확인일·검수 상태

미입점 상태에서는 다음 방식만 허용한다.

- 정보 제공
- 문의 요청
- 전화·메신저
- 공식 외부 링크

## 9.3 업체 페이지 소유권 인수

```text
파트너 가입
→ 기존 업체 검색
→ 소유권 요청
→ 사업자·담당자·공식 채널 증빙
→ 플랫폼 심사
→ 기존 Provider/Place 연결
→ 운영 권한 부여
```

새 페이지를 만들지 않고 기존 URL·리뷰·저장·스토리·랜드마크 관계를 유지한다.

## 9.4 데이터 품질

- `UNVERIFIED`
- `BASIC_VERIFIED`
- `PARTNER_VERIFIED`
- `PLATFORM_VERIFIED`
- `API_VERIFIED`

운영시간·가격·연락처·휴무·폐업을 주기적으로 검수하고 30·60·90일 재검수 정책을 적용한다.

- 회원의 과거 숙박 호텔 제안

## 14.2 결과·필터

- 가격·등급·평점
- 조식·무료 취소·즉시 확정

- 추천·가격·거리·평점 정렬

가격·재고에는 매진, 공급자 미응답, 오래된 데이터, 최근 확인 시각을 명확히 표시한다.

## 14.3 호텔 상세

- 요금·식사·세금·취소조건·총액·잔여수량
- 호텔에서 시작하는 하루와 관련 스토리

## 14.4 PMS 정보와 공개 콘텐츠 결합

```text
Hotel_PMS
Tenant + RoomType + Rate + Inventory
        │
        ├─ tenantId + pmsRoomTypeId
        │
HotelNGo 호텔 콘텐츠센터
소개 + 정책 + 편의시설 + 호텔/객실 사진
        │
        ▼
B2C 호텔·객실 상세
```

## 14.5 예약

```text
가격·재고 재검증
→ 재고 Hold
→ HotelNGo 예약
→ PMS 또는 공급자 예약
→ 외부 예약번호 연결
```

공급자 예약 생성이 실패하면 확정으로 표시하지 않고 대기 또는 대사 필요 상태로 관리한다.

# 16. AI 여행과 RAG

## 16.1 AI 여행의 역할

AI 여행은 별도의 여행 데이터가 아니라 수동 일정과 같은 구조의 `TripDraft`를 만들어 주는 생성·수정 도구로 구축한다.

## 16.2 사용자 입력

- 목적지 또는 목적지 추천
- 기간·날짜·인원·동행 유형
- 예산·숙박 선호·분위기
- 필수 장소·골프 횟수·음식 취향
- 마사지·이동수단·활동 강도
- 자유시간·제외 활동·특별 요청

## 16.3 결과

- 여행 제목·요약·추천 이유
- 날짜·시간대별 전체 일정
- 숙소·식사·랜드마크·활동·이동
- 이동시간·체류시간·예상비용
- 예약 가능 상태·대체 후보
- 경고·근거·신뢰도·정보 확인 시각

## 16.4 수정 명령

- 이동을 줄여줘
- 예산에 맞춰줘
- 호텔을 바꿔줘
- 골프를 추가해줘
- 부모님에게 편하게 바꿔줘
- 아이와 갈 수 있게 바꿔줘
- 비 오는 날 일정으로 바꿔줘
- 하루를 비워줘

## 16.5 처리 구조

```text
사용자 문장
→ 구조화된 여행 조건
→ 검수 콘텐츠/RAG 검색
→ 호텔·업체·지도·운영시간·날씨 도구
→ 일정 초안
→ 규칙 검증
→ 오류·충돌 수정
→ 가격·재고 재검증
→ 사용자 편집
→ 여행 카트
```

## 16.6 정보 원칙

| RAG로 제공 | 실시간 도구로 제공 |
|---|---|
| 도시·랜드마크 설명 | 객실 요금·재고 |
| 여행 스토리·가이드 | 티타임·차량·예약 슬롯 |
| 계절·가족·커플 팁 | 운영시간·휴무 |
| 검수된 업체 소개 | 최종 금액·쿠폰 |
| 정책 설명 | 예약·취소·환불 상태 |

AI는 원천 DB·결제·예약 시스템에 직접 접근하지 않으며 사용자 확인 없이 예약을 확정하지 않는다.

# 19. 호텔 콘텐츠센터

## 19.1 목적

Hotel_PMS가 관리하는 운영 데이터에 B2C 판매용 콘텐츠를 덧붙이는 독립 호텔 운영 영역으로 구축한다.

## 19.2 메뉴

| 그룹 | 메뉴 |
|---|---|
| 현황 | 콘텐츠 대시보드, 소유권·승인 |
| 공개 콘텐츠 | 호텔 소개·정책, 객실 매핑, 사진, 편의시설 |
| 연동 | PMS 연결, B2C 미리보기 |
| 계정 | 담당자·권한, 알림·설정 |

## 19.3 관리 항목

- 호텔 대표·공간·부대시설 사진
- 다국어 소개·특징·주변 정보
- 체크인·아동·반려동물·접근성·주차 정책
- PMS 객실유형별 여러 장의 사진
- 객실 크기·침대·전망·욕실·수용인원
- 대표 사진·순서·대체텍스트·공개 상태

## 19.4 책임 경계

- PMS의 객실유형·요금·재고·예약은 원천으로 유지한다.
- 호텔 콘텐츠센터에서는 PMS 재고를 수정하지 않는다.
- 객실 콘텐츠는 `tenantId + pmsRoomTypeId`로 연결한다.
- 객실 매핑이 끊기면 공개하지 않고 검수 대상으로 관리한다.

# 22. PMS 채널 운영과 Hotel_PMS 연동

## 22.1 연동 원칙

- Hotel_PMS를 `INTERNAL_PMS` 호텔의 원천 시스템으로 사용한다.
- HotelNGo는 PMS와 독립된 B2C·플랫폼으로 운영한다.
- PMS의 JSON·파일·브라우저 저장소를 직접 읽지 않는다.
- 기존 객실·요금·재고·예약 테이블을 복제하지 않는다.
- 공개 채널 API와 PMS 내부 운영 API를 분리한다.

## 22.2 매핑

| Hotel_PMS | HotelNGo |
|---|---|
| Tenant | 공개 호텔 |
| RoomType | 객실 Product |
| 날짜별 요금 | Offer/Rate |
| 객실 상태·예약 | 객실유형별 Availability |
| Reservation | 공급자 예약 |
| Guest | `PmsGuestLink` 참조 대상 |
| 물리 호실·직원·Folio | 공개 제외 |

## 22.3 HotelSupplyAdapter

조회:

- 호텔 검색
- 호텔 상세
- 객실 가용수량
- 객실 요금

예약:

- 재고 Hold·해제
- 예약 생성·변경·취소
- 예약 상태 조회
- 예약 대사

## 22.4 채널 운영 메뉴

# 25. 디자인·브랜드·고객경험

## 25.1 브랜드 방향

- 브랜드 표기: `HotelnGo`

- 지도 마커 `O`를 목적지 발견과 이동의 핵심 아이덴티티로 사용한다.

## 25.2 디자인 방향

- 한국 사용자가 익숙한 명확한 정보 구조
- 해외여행 우선
- 감성 콘텐츠와 거래 정보의 시각적 구분
- 친근하지만 가볍거나 저가처럼 보이지 않는 톤
- 넓은 여백보다 콘텐츠 밀도와 비교 효율을 우선
- 대표 이미지와 실제 선택 정보를 함께 제공

## 25.3 타이포그래피

- Pretendard Variable을 기본 인터페이스 폰트로 사용한다.
- 본문은 16px를 기본으로 한다.
- 실제 정보는 12px보다 작게 만들지 않는다.
- 카드·필드·버튼의 텍스트 크기와 굵기를 일관되게 유지한다.

## 25.4 인터랙션

- 주요 버튼 44px
- 카드 조작 38px
- 필터 칩 32px 이상
- 공통 선택 메뉴와 키보드 탐색
- 삭제·복원·저장·추가에 아이콘과 텍스트 병행
- 입력·선택·버튼 높이 정렬
- 드롭다운·팝업·캐러셀 버튼이 화면이나 카드에 가려지지 않게 한다.

## 25.5 반응형

- 데스크톱·태블릿·모바일을 모두 지원한다.
- 모바일은 Drawer와 하단 탭을 사용한다.
- 카드와 조작군은 좁은 화면에서 억지로 축소하지 않고 행을 재배치한다.
- 이미지·표·목록·일정이 가로로 잘리지 않게 한다.

## 29.6 사업성 검증 방식

각 KPI는 출시 전 임의 목표를 정하기보다 다음 순서로 확정한다.

1. 고객 인터뷰와 사용성 테스트로 행동 가설을 검증한다.
2. 한 도시에서 공급 밀도와 요청 예약 전환을 측정한다.
3. 소규모 유료 유입으로 CAC와 예약 전환을 측정한다.
4. 수수료 수익에서 변동비를 차감한 공헌이익을 계산한다.
5. 공헌이익과 반복 구매가 검증된 뒤 도시와 광고비를 확대한다.

# 32. 사업 추진 의사결정 Gate

## Gate 1 — 문제·고객 검증

- 여행자가 다일정 조합의 어려움을 실제로 느끼는가?
- 감성 콘텐츠가 목적지 선택과 저장 행동을 만드는가?
- 직접 일정과 AI 일정 중 어떤 방식의 선호가 높은가?

## Gate 2 — 공급 검증

- 1차 도시의 호텔·골프·차량·스파·투어를 충분히 확보할 수 있는가?
- 업체가 상품·자원·슬롯을 관리할 의사가 있는가?
- 요청 예약 SLA를 운영할 수 있는가?

## Gate 3 — 거래 검증

- 가격 경쟁력과 재고 신뢰도를 확보할 수 있는가?
- 요청 예약이 실제 확정으로 전환되는가?
- 호텔 외 상품이 객단가와 수익을 높이는가?

## Gate 4 — 단위경제성

- 예약당 공헌이익이 양수인가?
- CAC 회수 기간이 허용 범위인가?
- 취소·환불·CS·현지 운영 비용을 감당할 수 있는가?

## Gate 5 — 확장

- 한 도시에서 재방문·공급 안정성·운영 품질이 검증되었는가?
- 새 도시에서도 같은 공급·콘텐츠·운영 모델을 반복할 수 있는가?
