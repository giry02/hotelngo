# HotelnGo 모바일 UX 및 여행기 커뮤니티 점검 보고서

## 1. 점검 기준

- 점검일: 2026-08-26
- 화면 폭: 모바일 375×844px
- 점검 동선: 홈 → 여행 발견 → 여행 만들기 → 호텔 검색 → AI 여행 → 내 여행 → 여행기 목록 → 여행기 상세
- 점검 방법: 실제 브라우저에서 화면 이동, 가로 넘침, 터치 영역, 로그인 전후 행동, 댓글·스크랩 저장을 확인
- 데이터 방식: JSON fixture + 브라우저 Mock API 상태 저장. 실제 서버 API와 미디어 업로드는 후속 연동 범위

## 2. 사용자 관점 핵심 진단

### P1 · 먼저 개선할 항목

1. **홈의 첫 화면이 검색과 광고에 집중되어 여행기 발견이 늦다.**
   - 현재 첫 화면에서는 히어로와 검색 영역이 대부분을 차지한다.
   - 여행자의 실제 일정은 별도 메뉴와 홈 중간 진입 배너로 연결해야 한다.

2. **작은 터치 영역이 일부 남아 있다.**
   - 홈 히어로 이전·다음 버튼은 실제 23px 수준이다.
   - 여행 만들기 단계 번호는 약 30px, 호텔 목록의 필터·보기 전환은 약 36px, 내 여행 보조 탭은 약 34px이다.
   - 모바일 핵심 조작은 최소 44×44px을 기준으로 확대해야 한다.

3. **여행 발견의 가로 카드가 스와이프 가능한지 바로 알기 어렵다.**
   - 화면 밖 다음 카드가 일부 보이지만, 페이지 표시나 `옆으로 넘겨보기` 안내가 없다.
   - 첫 진입 시 한 번만 노출되는 스와이프 힌트와 현재 위치 표시가 필요하다.

4. **여행 만들기의 단계 이동은 구조는 명확하지만 작은 단계 컨트롤과 긴 설명이 부담스럽다.**
   - 단계 제목 전체를 누를 수 있도록 터치 영역을 확장하고, 현재 결정한 여행지·기간을 상단 요약으로 유지해야 한다.

5. **호텔 검색의 필터 칩과 보기 전환이 촘촘하다.**
   - 선택된 필터를 한 줄 요약으로 접고, 상세 필터는 모바일 바텀시트로 여는 방식이 더 적합하다.

### P2 · 사용성을 높일 항목

1. 홈 히어로의 자동 전환 상태와 일시정지 제어를 더 명확히 표시한다.
2. AI 여행과 일반 여행 만들기의 차이를 첫 진입 문구와 결과 형태로 구분한다.
3. 내 여행의 `여행 일정 / 예약 내역 / 저장·찜 / 활동·혜택` 탭은 글자만이 아니라 아이콘과 상태 건수를 함께 제공한다.
4. 모바일에서 긴 필터·태그 행은 브라우저 전체 가로 스크롤이 생기지 않도록 컨테이너 내부 스크롤로 제한한다.

## 3. 이번 반영 내용

### 여행기 메뉴와 콘텐츠 진입

- 데스크톱 상단 메뉴와 모바일 하단 고정 메뉴에 `여행기`를 별도 1차 메뉴로 추가했다.
- 모바일 하단 메뉴를 `홈 / 여행기 / 만들기 / 호텔 / 내 여행`의 5개 구조로 정리했다.
- 문자 기호 대신 동일한 선형 SVG 아이콘을 사용하고 현재 메뉴를 주색으로 표시한다.
- 페이지별 스크립트 구성과 관계없이 공통 모바일 전체 메뉴가 열리고 닫히도록 셸에서 초기화한다.

### 여행기 피드

- 작성자 아바타, 작성자명, 공개 여행 수, 여행지, 기간, 태그, 일정 일수를 노출한다.
- 카드에서 좋아요, 댓글, 스크랩, 공유를 바로 실행할 수 있다.
- `여행기 보기`와 `내 여행에 담기`를 분리했다.
  - 스크랩: 다시 볼 콘텐츠를 저장한다.
  - 내 여행에 담기: 원본과 독립된 편집 가능한 여행 일정을 만든다.

### 여행기 상세와 참여

- 작성자 팔로우, 좋아요, 댓글, 스크랩, 공유를 한 영역에서 제공한다.
- 날짜별 일정과 예약 방식은 그대로 확인하되, 내 여행에 담은 뒤 자유롭게 바꿀 수 있음을 설명한다.
- 댓글 목록과 댓글 작성 폼을 추가하고 실제 Mock 데이터로 저장되도록 연결했다.
- 공유는 지원 기기에서 시스템 공유 패널을 사용하고, 미지원 환경에서는 링크 복사로 대체한다.

### 로그인 경계

- 여행기 열람과 링크 공유는 비로그인 상태에서도 가능하다.
- 좋아요, 스크랩, 댓글, 팔로우, 내 여행에 담기는 로그인이 필요하다.
- 비로그인 사용자가 회원 기능을 누르면 현재 여행기 주소를 유지한 로그인 화면으로 이동하고, 로그인 후 같은 화면으로 돌아온다.

### Mock API 도메인

- `community-engagements`: 회원별 좋아요·스크랩 상태
- `community-comments`: 여행기 댓글
- `community-follows`: 작성자 팔로우 상태
- `trips`: 여행기를 내 여행으로 복사한 독립 일정
- 각 변경은 감사 이벤트에 기록하며, 이후 REST API로 교체할 수 있는 경계를 유지한다.

## 4. 모바일 검증 결과

- 여행기 목록과 상세에서 문서 전체 가로 넘침: 없음
- 모바일 하단 메뉴: 5개 모두 표시, 여행기 현재 위치 표시 정상
- 여행 만들기처럼 공통 스크립트가 없던 화면의 햄버거 메뉴: 열기·닫기 정상
- 여행기 상세 소셜 기능: 좋아요·댓글·스크랩·공유 4종 표시 정상
- 비로그인 좋아요 실행: 로그인 화면 이동 및 원래 여행기 주소 보존 정상
- 로그인 후 스크랩: 상태 저장 및 버튼 상태 변경 정상
- 로그인 후 댓글: 목록 즉시 반영 정상
- 공개 샘플: 교토, 다낭, 방콕 여행기에 날짜별 일정과 실제 댓글 fixture 제공

## 5. 실제 서비스 전 추가해야 할 운영 기능

1. 댓글 신고·숨김·차단·관리자 검수
2. 이미지·동영상 업로드, 저작권 동의, 유해 콘텐츠 필터링
3. 좋아요·댓글·팔로우 알림과 활동 피드
4. 인기·최신·팔로잉 추천 알고리즘과 중복 여행기 제어
5. 작성자 프로필, 팔로워 수, 여행 신뢰도와 방문 인증
6. 공개 범위, 링크 공유 만료, 여행 동행자 개인정보 제거 검증
7. 커뮤니티 콘텐츠와 PMS·예약 데이터의 명확한 분리
