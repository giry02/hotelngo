# HotelnGo 독립 모바일 웹·하이브리드 실행 기준

## 1. 확정 원칙

- 모바일은 PC 화면을 축소하는 반응형 복제본이 아니다.
- `/mobile/index.html`을 진입점으로 하는 독립 모바일 앱을 운영한다.
- PC 웹 HTML·CSS와 모바일 HTML·CSS는 서로 참조하지 않는다.
- 회원, 여행 카드, 일정, 커뮤니티, 호텔 및 예약 데이터 계약은 공유한다.
- 하이브리드 앱은 Capacitor가 `/mobile` 웹 자산만 패키징한다.

## 2. 화면 책임

| 모바일 영역 | 사용자 목표 | 주요 인터랙션 |
|---|---|---|
| 홈 | 다음 행동을 바로 결정 | 검색, 이어 만들기, 여행기 스와이프 |
| 여행 발견 | 지역과 장소를 탐색 | 지역 선택, 필터, 여행 카드 담기 |
| 여행기 | 다른 사람의 경험을 활용 | 좋아요, 댓글, 스크랩, 공유, 내 여행 복사 |
| 여행 카드 | 가고 싶은 후보를 모음 | 삭제, 추가, AI 일정 초안 생성 |
| 일정 | 날짜별 시간과 동선을 확인 | DAY 전환, 시간·체류시간 변경, 저장 |
| 호텔 | 일정에 맞는 숙소를 비교 | 검색, 필터, 여행 카드 담기, 객실 선택 진입 |
| 내 여행 | 일정과 예약을 통합 조회 | 일정 편집, 예약 준비, 저장·활동 확인 |

## 3. 공유 계약

- 세션: `hotelngo.mock.session.v1`
- 여행 카드: `hotelngo.api.state.v1.trip-card`
- 여행 일정: `hotelngo.api.state.v1.trips`
- 커뮤니티 반응: `hotelngo.api.state.v1.community-engagements`
- 커뮤니티 댓글: `hotelngo.api.state.v1.community-comments`
- 현재는 JSON·브라우저 저장소를 사용하며 실제 서버 API로 교체 가능한 경계를 유지한다.

## 4. 모바일 전용 기준

- 주요 터치 영역은 최소 44px로 한다.
- 5개 하단 탭을 핵심 내비게이션으로 사용한다.
- 복잡한 선택은 작은 풀다운 대신 바텀시트로 제공한다.
- 여행기와 발견 화면은 스와이프·스크롤 중심으로 구성한다.
- 로그인하지 않은 사용자는 탐색·열람·공유만 가능하다.
- 저장, 댓글, 스크랩, 일정 복사 및 예약은 로그인 후 가능하다.
- 여행 카드와 실제 예약은 명확하게 분리한다.

## 5. 하이브리드 연결

- 웹: Web Share API, Clipboard, Geolocation, Service Worker를 사용한다.
- 앱: Capacitor Share, Haptics, Geolocation 플러그인으로 교체된다.
- `scripts/native-bridge.js`가 웹과 앱의 호출 차이를 흡수한다.
- Android와 iOS 네이티브 프로젝트는 `npm run mobile:sync`로 `/mobile` 자산과 동기화한다.

## 6. 향후 서버 전환

1. JSON Fixture를 `/api/v1/mobile/bootstrap` 조회로 전환한다.
2. 브라우저 저장소 쓰기를 회원 API와 여행 API 명령으로 교체한다.
3. 이미지 업로드, 댓글 알림, 신고·차단과 콘텐츠 검수를 추가한다.
4. 지도·경로 계산을 실제 지도 및 라우팅 API로 교체한다.
5. Hotel_PMS와 예약·재고 연동은 HotelnGo 플랫폼 API를 통해서만 연결한다.
